# Dementia and frailty integration roadmap — design only

**Boundary:** the NHS Parliamentary Lens in this repository owns dated PCON24, MP, NHS organisation address, explicit RE6 and GP registration relationships. [`OPL-Advisory/local-health-data-explorer`](https://github.com/OPL-Advisory/local-health-data-explorer) remains the separate authoritative **dementia-first** place and measure product. No Local Health Data Explorer data, presentation renderer, held frailty asset or unreleased measure is copied into this site. `OPL-Advisory/dementia-explorer` is a historical reference, not an implementation base.

This assessment read the current Explorer `docs/brief/NEXT_IMPLEMENTATION_BRIEF.md`, `docs/brief/DATA_COVERAGE_MATRIX.csv`, `docs/decisions-data-publication.md`, `docs/BUILD-SESSION-BRIEF.md` and `docs/release-readiness.md` on 10 October 2026. The governing brief starts from accepted data/provenance candidate `b70db8d8bc7f7cc0e247bc4edfe4c4bbdd55ed24`, mandates a validated read-only import by candidate ID, accepted period, inventory, hashes and place counts, and makes the public module dementia only. Its place registry and canonical measure registry are the source of identity and value semantics **inside that product**. Its data-publication decision file still states “open”; it recommends release assets but records unresolved custody, accepted hash and rollback questions. This roadmap does not settle or bypass that decision.

## Future interoperability contract

| Shared concept | Required join and proof | What the parliamentary site may show |
|---|---|---|
| GP practice identity | Exact ODS code plus explicit `place_type=gp_practice`, observed in an accepted Explorer place registry with a compatible code history | A clearly labelled outbound link to that Explorer practice record **after** its URL contract and published candidate are verified. A matching code does not copy its dementia values to a constituency. |
| Other NHS organisation | Exact ODS code *and* an Explorer-supported `place_type`; many site/trust codes in the spine have no Explorer measure record | Only an identity link if the destination actually exists and is public. No nearest-name, postcode, ICB or RE6 substitution. |
| Parliamentary constituency | PCON24 code and July 2024 boundary in this site's own release | MP and geography context, plus separately labelled GP registration links. PCON24 is not an Explorer ICB/sub-ICB/PCN/practice hierarchy node. No constituency “dementia value” is derived from an address or practice list. |
| Measure value | Explorer `measure_id`, `topic`, `source_id`, `place_id`, period, `geography_vintage`, numerator/denominator, availability and `promotion_state`, with accepted candidate/hash identity | Ideally an outbound deep link to the Explorer's *own* public canonical model. If a small preview is later approved, it must be a read-only, hashed export of that same accepted model; this site cannot calculate, select fallback periods, or alter availability. |

The brief's canonical model is keyed by `place × measure × period × source`; missing, unsupported, not published, suppressed and held are distinct states, and a numeric zero remains available. Cross-app links must never erase those distinctions. A publisher-approved allowlist of **public** dementia measures and exact source/period IDs is required before a preview is built. The Explorer's `DATA_COVERAGE_MATRIX.csv` is the completeness ledger: e.g. EDDR is supported for England, region, ICB and sub-ICB but not PCN/practice; practice data has explicit absence cases. The publication gate, not mere presence in a file, decides public availability. All frailty records in the inspected matrix are held, including core management information and expected-frailty research previews; they remain absent from this site's navigation, assets and previews until a distinct authorisation and release gate changes their status.

## Staged pathway

1. **Identity linking only.** Agree a stable Explorer URL schema and accepted public candidate with its owner. Produce a manifest of exact `place_type + code` matches, nonmatches and code-history conflicts. Test that links resolve to a public place identity. A PCON page can link to individual practices in its GP-registration list, with “practice profile” wording and existing registered-patient caveats. It must not say a constituency's residents have the practice's dementia measure.
2. **Read-only public measure pointers.** After the Explorer promotion gate and publication decision are settled, accept a small versioned link/index artifact listing public dementia `place_id`, `measure_id`, period, source, `geography_vintage`, availability and candidate hashes. Validate it against the Explorer's accepted release manifest. Show a source-bound outbound link, or an explicitly copied **place-level** canonical record with the source period beside it. Never apply the measure to another geography because a GP site or operator maps there.
3. **Future policy and research context.** The [10 Year Health Plan](https://www.gov.uk/government/publications/10-year-health-plan-for-england-fit-for-the-future/fit-for-the-future-10-year-health-plan-for-england-accessible-version) proposed Modern Service Frameworks including frailty and dementia. [NHS England's medium-term framework](https://www.england.nhs.uk/long-read/medium-term-planning-framework-delivering-change-together-2026-27-to-2028-29/) says dementia and frailty frameworks will follow the initial set. When an actual framework and definitions are published, a separate evidence review can ask which **published** measures illuminate access, diagnosis, care recording, inequalities, research transparency, or service availability at their true source geographies. The roadmap assumes no unreleased indicator definition, benchmark, target or care-performance score.

## Decision gates and tests for a later PR

- **Owner and publication:** the Explorer owner confirms accepted candidate, promotion states, public route contract, data delivery choice, licence and rollback. A held value remains held even if a route can technically render it. The Parliamentary Lens release remains separate.
- **Join and vintage:** exact ODS/place type, code-history and period checks pass; no postcode/name fallback. PCON24, ICB, sub-ICB, PCN and practice are different systems. A GP's patient allocation is aggregate registered-population context, not a count of dementia diagnoses or opt-outs by constituency.
- **Semantic review:** use the Explorer registry's numerator/denominator, unit, uncertainty, comparator and warning policies verbatim; no ecological causal claim, ranking of MPs/constituencies, implied service accountability, or extrapolation from a trust/ICB address.
- **QA:** match/nonmatch counts and hashes are reproducible; only `promotion_state=public` and supported place types are linkable; all held frailty IDs are absent from public assets; links and absence states work by keyboard and at mobile width; a candidate rollback restores the prior accepted link manifest.

**Next deliverable:** an owner-reviewed interoperability schema and small public-place link manifest, not a combined dashboard. The current v0.4 PR stops before that gate.
