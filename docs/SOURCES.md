`data/raw/sources_manifest.json` records the exact URL, source version/date and date meaning, UTC retrieval time, byte count and SHA-256 of each downloaded file. `data/processed/build_manifest.json` copies that provenance and adds the Git SHA, build time, row counts (including source-versus-selected `eother` rows), geography vintages and QA summary. The raw archives are never committed. ODS reports are retrieval snapshots, not immutable monthly publications. Their 27-column schemas are checked strictly. For v0.2 reports with no status column, `ACTIVE` means the legal end date is absent or after the retrieval date; it is not an independent operational-status assertion.

The member dimension is independently refreshed with `nhs-geo fetch --refresh-member` and rebuilt offline. A by-election or vacancy changes the current member snapshot without changing the July 2024 geographic code set. The build stores the Parliament constituency ID and source name as well as the ONS code/name. The normalized name bridge removes Unicode accents and case differences, then requires a one-to-one match across the entire code set. It does not fuzzy-match or select the closest name.

ODS column 15 (`TargetOrgCode`) is optional in `ebranchs`, `ets` and `eccgsite`. A row without it remains a site with null RE6 code and dates. `provider_coverage.missing_re6_operator_rows` identifies these rows; an active omission gives a QA warning. RE6 dates and parent type are validated when a target code is present.

## Geography and data-quality meaning

The postcode directory's `PCON` is a **direct postcode allocation** for the July 2024 constituency geography. A postcode can span addresses on both sides of a boundary; ONS assigns it from the postcode's reference location. The fallback from postcode LSOA to PCON is visibly marked and can differ from a direct allocation. Registered patients are allocated by the ONS **best-fit** LSOA lookup, which is not exact address-level or polygon-intersection geography.

England/Wales `lsoa_code` in `postcode_spine.parquet` means 2021 LSOA. The same source column has Scottish Data Zones and Northern Irish Super Data Zones for those countries. It must not be joined to the England/Wales best-fit lookup. The GP patient file also contains `EMPTY`, `CLOSED`, and small-area codes outside England/Wales. Those rows remain in an explicit `UNMAPPED` practice bucket and a reasoned detail table. The July CSV total differs from the release-page headline by six; no cause is assumed here.

The GP adapter still selects RO76 practices, including England and Wales because `epraccur` contains both. The patient data cover England GP registrations only. An ODS practice without a patient-file row remains in the site bridge. A patient-file practice without an ODS site row remains in the patient bridge. Neither relationship is manufactured. Provider and commissioner site mappings use the same direct-postcode, labelled-LSOA-fallback and explicit-unmapped sequence, but no patient catchment is derived for them.

## v0.2 coverage and relationship limits

| Published type | ODS source/role | Site or organisation address | Explicit operating link |
| --- | --- | --- | --- |
| GP practice | `epraccur`, RO76 non-primary of prescribing cost centre RO177 | England and Wales; unchanged v0.1 file | No parent claim from `epraccur` commissioning/geographic fields. |
| GP branch surgery | `ebranchs`, RO96 | England and Wales; request-driven code coverage | RE6 to prescribing cost centre. A target outside the selected GP set stays unresolved. |
| NHS trust, including foundation trusts | `etr`, RO197 | England-only report | Foundation RO57 subtype unavailable in this predefined CSV. |
| NHS trust site | `ets`, RO198 | England and Wales report, including a few overseas site postcodes | RE6 to trust; one code does not imply one hospital. |
| ICB | `eother` filtered by ONS ICB26CDH, RO261/RO318 | **Current April 2026 code set only**; England | No ICB site or trust partnership relationship inferred from a postcode or name. |
| Sub ICB location, reporting entity, commissioning hub, ICB commissioning proxy, former CCG | `eccg`, RO98 plus reported non-primary role where present | England | Source CSV has no explicit ICB parent relationship; high-level health geography is postcode derived and is not treated as one. |
| Sub ICB location site | `eccgsite`, RO99 | England | RE6 to RO98 unit. These are commissioner site codes, not a general list of ICB offices. |

The expanded dimension includes all rows in the single-role DSE reports, active and inactive; the mixed `eother` report is explicitly filtered against the frozen ONS ICB set. The April 2026 list excludes abolished ICB codes and will need a deliberate refresh when the ICB code set changes. Branch RE6 targets can be non-RO76 prescribing cost centres in `epraccur`; v0.2 preserves their target code and lists unresolved links rather than inventing a GP operator. It also flags active branches whose resolved GP operator has a non-`ACTIVE` source status (15 `DORMANT` targets in the 9 October run); no operational conclusion is inferred from that flag. Dates are source legal dates and RE6 dates only where the predefined report supplies them. `pcon_nhs_organisations` filters to active, mapped **addresses**. Its parent context describes an operator, not the parent’s service territory. `pcon_provider_summary` includes every active mapped type, including commissioner codes. It counts ODS codes and must not be read as a count of distinct hospitals or patients.

## Licences and attribution

The [ONS geography licences page](https://www.ons.gov.uk/methodology/geography/licences) states that the LSOA lookup is under OGL v3 and asks for: “Source: Office for National Statistics licensed under the Open Government Licence v.3.0”. For the postcode directory it also requires “Contains OS data © Crown copyright and database right 2026” and “Contains Royal Mail data © Royal Mail copyright and database right 2026”. **Northern Ireland postcode data require the separate LPS End User Licence for internal business use; commercial reuse requires a separate licence.** Review those terms before distributing the full UK postcode table or DuckDB bundle. This repository distributes code and source pointers, not the datasets.

[NHS England's terms](https://digital.nhs.uk/about-nhs-digital/terms-and-conditions) make its content available under the current OGL unless otherwise specified and require attribution for adapted content: “Contains information from NHS England, licenced under the current version of the Open Government Licence”. The GP patient publication is aggregate open data; source quality limitations remain those in its [data quality statement](https://digital.nhs.uk/data-and-information/publications/statistical/patients-registered-at-a-gp-practice/data-quality-statement).

## Refresh procedure

1. Check the official ONS lookup, NHSPD and April 2026 ICB code items, the seven ODS report specifications above, and the NHS England GP registration series. Keep the geography vintage fixed at PCON July 2024 unless intentionally planning a migration. Confirm a patient ZIP explicitly contains **2021** LSOA and the ALL-persons member.
2. Update `config/sources.yml` with the verified resource URL, version, source date and ZIP member paths. The current file is pinned and runnable; the pipeline does not guess a new monthly/quarterly URL from a publication title.
3. Run `nhs-geo fetch --refresh`, `nhs-geo build --offline`, `nhs-geo qa`, `pytest -q`, and `ruff check src tests`. For a member-only update, run `nhs-geo fetch --refresh-member` followed by the same offline build and QA. Inspect `build_manifest.json` hashes, `qa_report.json` mapping misses by organisation type, unresolved RE6 codes, member/vacancy coverage, source-versus-bridge patient totals, fallback counts and warnings. A schema or geography change fails the build rather than silently adapting.
4. Keep the exact raw archives plus manifest in controlled storage outside Git for any published release. Date the QA and attribution supplied with a downstream export. The generated Parquet, CSV and DuckDB files remain ignored by Git.

For a later UK-wide expansion, identify defensible nation-specific ODS provider and commissioner reports, extend **site locations** with direct postcode mapping and licence review, and add separate **served population** flows only where source data support them. Scotland Data Zones and Northern Ireland SOAs are not England/Wales LSOAs. Revisit current-versus-historic ICB code coverage and RO57 foundation subtype through a source that actually provides those roles.
