# National Data Opt-Out integration spike — 10 October 2026

**Decision: keep National Data Opt-Out out of the public Parliamentary Lens release.** The evidence supports a separately labelled, dated **practice context** record joined by exact ODS practice code after a current official CSV is acquired and checked. It does **not** support observed constituency-resident opt-out rates from practice data. This PR includes only an offline research adapter and synthetic tests; `web/` contains no opt-out values or links to the research output.

NHS England describes the national preference as a choice about confidential patient data use for **research and planning beyond individual care**. It is not a measure of trust, willingness to participate in research, dementia diagnosis, clinical quality, or service performance. The [dashboard metadata](https://digital.nhs.uk/dashboards/national-data-opt-out-open-data) defines the opt-out count as unique NHS numbers excluding deceased people, `List Size` as GP-registered people excluding deceased, and `Opt-out rate` as their ratio. Rates are not age or demographic adjusted. The practice list size belongs to the **same NHS England opt-out row and date**; the spine's 1 July 2026 GP registration extract must not replace it.

The [NHS England site terms](https://digital.nhs.uk/about-nhs-digital/terms-and-conditions) generally apply the current Open Government Licence to NHS England content unless otherwise stated, with attribution and no implied endorsement. Confirm the actual CSV's notices before any redistribution. The historical derived files in a private repository are not a new public licence grant.

## Tested ODS join, with its limit

The offline adapter in [`spikes/opt_out.py`](../spikes/opt_out.py) reads a locally obtained NHS England geography CSV at **one explicit date**, groups `Practice Code × Date × Measure Names`, hashes the source in chunks, and joins only to `organisation_parliamentary_profile.parquet` on the exact ODS code. It uses the official `Opt-out`, `List Size`, and `Opt-out rate` measures, excludes the separate `Deceased` measure, rejects duplicate measure keys or inconsistent count/rate/denominator pairs, and retains unknown/suppressed/zero as different states. It emits a bounded sample and reason counts. A PCON code, when present, is named `spine_address_pcon24cd_context_only`; the adapter emits **no constituency opt-out numerator, denominator, or rate**.

The synthetic test fixture has four practice-code rows at 5 August 2026: one mapped GP address, one unmapped GP address, one code that maps to a non-GP spine organisation, and one code absent from the spine. Its join reason counts are **1 each**. One official count is `0`, another is suppressed (`*`), and an absent list size is unknown rather than zero. These numbers are illustrative test data, not NHS statistics.

For an **identifier-only historical check**, the existing project's derived `practices.csv` Git blob (`eb8e8f2346397e52739c3de4f986cd7ab12ca203`) was streamed against the accepted 10 October 2026 spine profile without storing rows in this repository:

| Join reason | Codes |
|---|---:|
| Matched GP with mapped address | 6,412 |
| Absent from spine snapshot | 11 |
| Duplicated source practice code | 0 |
| Total historical codes | 6,423 |

This 99.8% code match is **not** current official weekly-data coverage and does not validate counts, list sizes, ICB assignments, date alignment, or patient residence. The 11 missing codes need code-history review; name matching or silent code substitution is prohibited. The current weekly CSV could have different codes, geography and missingness. A release candidate needs a new official download hash, date-specific row and unique-key counts, per-measure missing/suppressed/zero counts, exact-code match reasons, and source-versus-spine periods recorded together.

## Geography compatibility

| Geography | Official source evidence | Relationship to the spine | Publish judgment |
|---|---|---|---|
| GP practice | Weekly practice ODS code, source opt-out count, official `List Size` and rate | Exact ODS code can identify a GP profile. Its address PCON is **location only**. | **Potential practice context** after current CSV ingestion, provenance/quality checks, licence review and a separate release decision. |
| Parliamentary constituency (PCON24) | No current PCON24 resident field in the weekly practice CSV | The site's GP patient shares come from an earlier aggregate LSOA21 allocation. They do not reveal which registered people opted out. A practice address can differ from its patients' constituencies. | **Do not publish constituency opt-out figures.** Summing practice counts by address or allocating them using aggregate shares would manufacture residence-level observations. |
| ICB / sub-ICB | Geography CSV provides practice mappings where known; historical release has registered and resident tables | NHS administrative hierarchy, source period and code vintage must be checked. Practice-registered geography is distinct from a resident distribution. | Investigate as an explicitly dated official aggregate, only if its own source grain, denominator and coverage are verified. Do not infer an ICB population from a location record. |
| NHS region | Official dashboard reports region rates; source geography metadata includes commissioning region | Region definition and date may differ from another source's region | Potential official aggregate, labelled with its own geography and reporting period; no constituency inference. |
| Historic resident LSOA / LA | Separate April 2023 resident-geography file | Historic vintage, suppression, denominator and methodology require review; LSOA-to-PCON24 lookup is many-to-many in reality and best-fit is approximate | **No current PCON claim.** A future model would need explicit uncertainty, denominator and privacy review, and must be labelled an estimate; it would remain separate from observed official figures. |

## Recommendation and next gate

1. Keep the present public site to v0.3 geography, membership, ODS and GP registrations. **Do not add opt-out data in this PR.**
2. Obtain and retain the current official geography CSV with a SHA-256, download timestamp, source date, notice and a bounded extract. Run the adapter and document join reasons and measure states for an explicit week. Validate rate scale, deceased exclusions, code history and practice list size against the official metadata. Inspect small-cell and privacy requirements before a practice page is considered.
3. If a practice-context module is proposed, define it in its own dated release asset and editorial review; describe a practice's *registered* population, not the constituency's residents. Do not treat Type 1 as the National Data Opt-Out series.
4. A constituency-resident product needs an independently published observed resident-geography source with compatible date and boundary, or a separately approved formal model with uncertainty and non-identifiability stated. Neither exists as a publishable PCON24 result in this assessment.

Reproduce the safe fixture: `python -m pytest -q tests/test_opt_out_spike.py`. For a controlled official local file: `python -m spikes.opt_out --geography-csv /path/to/geography.csv --profiles data/processed/organisation_parliamentary_profile.parquet --date YYYY-MM-DD`. The default report is ignored under `data/opt-out-spike/`; it is a research sample, not a website asset.
